日本の住所は、同じ場所でも書き方がばらばらです。全角と半角、「1-2-3」と「1丁目2番3号」、建物名や部屋番号が1行に混ざった書き方。日本語が読めない海外の開発者や越境ECにとっては、配送ラベルに英語で書くことさえ難しいのが現状です。その住所を1回の呼び出しで整え、英語表記まで付けて返すWeb APIです。

**いまの状況**：全国すべての市区町村（約1,900）の住所データを取り込み、機能と評価まで完成しました。本番サーバーの構築手順（HTTPS化、自動起動、死活監視）も用意済みで、ドメインの取得とAPIマーケットプレイス（RapidAPI）での公開を進めています。

## できること

- 表記ゆれのある住所を、決まった形に整えます
- 建物名・棟・階・部屋番号を、番地と分けて返します
- 海外の配送フォームの欄（住所1行目・2行目・市区町村・都道府県・郵便番号・国）にそのまま入れられる英語表記を返します
- 公的な住所データとどこまで一致したか（町名まで、番地まで など）を判定し、郵便番号の食い違いなどを警告します
- 都道府県や市を省いた住所でも、候補の中から正しい場所を推定します。候補を絞りきれないときは、勝手に選ばずに「市区町村があいまい」と候補の一覧を返します
- 最大50件をまとめて処理でき、1件に問題があっても残りの結果は返します

## たとえば

`〒100-0005 東京都千代田区丸の内2-7-2 JPタワー 5階 501号室` を送ると、次のように分けて返します。

| 項目 | 結果 |
| --- | --- |
| 建物名・階・部屋 | JPタワー ／ 5階 ／ 501 |
| 住所1行目（英語） | 2-7-2 Marunouchi |
| 住所2行目（英語） | Room 501, JP Tower 5F |
| 市区町村・都道府県 | Chiyoda-ku, Tokyo |

## 「確認できない」ことも正直に返す

公的な住所データには、まだすべての番地が載っているわけではありません。そこで、確認できなかった番地も捨てずに残し、「番地は公的データで確認できなかった」という警告として返す設計にしました。黙って削ったり、確認済みのように見せたりすると、配送の事故や、正しい住所を誤りと判定する問題につながるからです。

## つくり方

住所を整える部分は、自前で書き直さずにデジタル庁が公開している ABR Geocoder（アドレス・ベース・レジストリを使う住所解析のオープンソース）を土台にしました。差別化は「英語表記」「建物名の分離」「実在確認」の3点に絞り、品質はここに集中させています。

全角や漢数字、地下階、京都の通り名、北海道の「条」など、152件の書き方を集めた評価用データを用意し、変更のたびに全件を自動で確かめています。現在は、建物名・階・部屋番号・住所1行目のすべてが152件とも期待どおりに分かれています。実装は Claude Code に任せ、どの機能を入れるか、何を正解とするかの判断は自分が担当しています。

## 調整に使っていない住所で確かめる

評価用データに合わせて調整を重ねると、そのデータだけに強いAPIになってしまいます。そこで、調整には一度も使っていない22件の住所（大阪・名古屋・京都・札幌・仙台・福岡・広島・神戸・那覇・金沢など）を別に用意し、全国データで試しました。採点のルールは事前に決めておき、結果を見てからAPIを直すことはしていません。

| 確かめたこと | 結果 |
| --- | --- |
| 住所部分 | 22件中22件 正解 |
| 都道府県や市を省いた5件 | 5件とも正しい場所を推定（別の都市を選んだものは0件） |
| 建物名・棟・階・部屋（正解を用意した6件） | 6件中5件 正解 |

外れた1件は、「堺市役所 本館」の「本館」を棟として分けなかったものです。いまは「A棟」「東棟」のような書き方だけを棟として扱っているためで、今後の改善点として記録しています。

## 使用技術

TypeScript、Hono、ABR Geocoder、kuromoji、SQLite、Vitest、Docker

## データの出典

「アドレス・ベース・レジストリ」（デジタル庁）、郵便番号データ（日本郵便株式会社）
