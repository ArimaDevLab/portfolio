「3営業日後はいつか」「20日締め翌月末払いだと、実際に振り込むのは何日か」。請求や納期のシステムで毎回必要になるのに、祝日や銀行の休み、会社ごとの休日まで正しく扱うのは意外と手間がかかります。その計算を1回の呼び出しで返すWeb APIです。

**いまの状況**：計算機能、APIキー認証、利用回数の制限、独自カレンダーまで実装とテストが済んでいます。本番環境へのデプロイと料金の確定、利用規約の整備を進めています。

## できること

- 指定した日が営業日かどうかを判定し、休みならその理由（土日・祝日・銀行休業日）と祝日名を返します
- 「N営業日後・前」の日付と、その間に飛ばした休日の一覧を返します
- 期間内の営業日数を数えます
- 締め日と支払条件から、実際の支払日を計算します
- 会社独自の休業日を「独自カレンダー」として登録し、どの計算にも使えます

## 同じ「3営業日後」でも、答えは変わる

2026年12月29日の3営業日後を計算すると、一般の暦（`standard`）では2027年1月4日、銀行の暦（`bank`）では1月5日になります。銀行は12月31日から1月3日まで休むためです。どの暦で数えるかを毎回指定するので、「なんとなく」の計算で日付がずれることがありません。

## 支払日の計算

たとえば「月末締め・翌月末払い・休日なら前倒し」で、2026年12月10日の請求を計算すると次のようになります。

| 項目 | 結果 |
| --- | --- |
| 締め日 | 2026年12月31日 |
| 約定上の支払日 | 2027年1月31日（日曜日） |
| 実際の支払日 | 2027年1月29日（金曜日） |

休日のときに前倒しにするか後ろ倒しにするかは契約ごとに違うので、あえて既定値を置かず、毎回指定してもらう設計にしました。黙ってどちらかに決めると、支払いの遅れや早すぎる振込という事故につながるからです。

## つくり方

先に仕様書を書き、業務ルールの判断が分かれる10か所（12月31日を営業日とするか、起算日を数えるか、締め日が休日のときにずらすか、など）を洗い出して、一つずつ理由をつけて決めました。そのうえで、仕様書に書いた50件の計算例をテストにしてから、Claude Code に実装を任せています。AIには「仕様書にないルールは自分で決めずに質問する」「テストが通らないときに期待値を書き換えない」と指示し、業務の判断は人間、実装はAIと役割を分けています。

祝日は内閣府が公表しているデータを使い、毎年の更新手順と、別のデータと突き合わせて食い違いを見つけるテストも用意しています。
